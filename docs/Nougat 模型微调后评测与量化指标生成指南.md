# Nougat 模型微调后评测与量化指标生成指南

**起点假设**：你已经完成了模型的微调，目前手头拥有原始预训练模型权重（Baseline）和微调后的模型权重（Finetuned）。

## 阶段一：评测物料准备 (Material Preparation)

为了进行严谨的、可写入简历的 A/B 测试（消融实验），你的服务器或本地硬盘上需要准备以下四类物理材料：

1. **模型权重对 (Model Weights)**
   - `nougat-base`：官方开源的预训练权重。
   - `nougat-finetuned`：你用 28800 张图跑完 Epoch 后保存的最佳权重（Checkpoint）。
2. **测试集图片 (Test Images)**
   - 数量：约 3200 张。
   - 来源：那 32000 张总数据中，**绝对没有参与过训练**的留出集。
   - 格式：模型输入所需的格式（通常是渲染好的图片或裁剪后的 PDF 页）。
3. **测试集标准答案 (Ground Truth - GT)**
   - 数量：约 3200 份。
   - 来源：与测试集图片一一对应的、你用 LaTeXML 跑出来的自定义 `.mmd` 文件。
   - 路径约定：统一存放在目录 `./data/test_gt/` 下。
4. **评测脚本 (Evaluation Scripts)**
   - 需要你编写的 Python 脚本，包含三个模块：批量推理模块、文本清洗模块、指标计算模块。

## 阶段二：执行操作蓝图 (Execution Blueprint)

评测的核心目的是量化微调带来的“增益（Gain）”。你需要执行以下三个步骤：

### Step 1: 批量双轨推理 (Batch Inference)

让两个模型分别对这 3200 张“没见过的”测试图片进行预测，生成两套结果。

- **操作**：编写一个推理循环（Inference Loop）。
  - 加载 `nougat-base`，遍历测试图片，将生成的 3200 份 `.mmd` 存入 `./data/pred_base/`。
  - 加载 `nougat-finetuned`，同样遍历测试图片，将生成的 3200 份 `.mmd` 存入 `./data/pred_finetuned/`。
- **算力与时间**：无需反向传播，仅做前向推理（Forward Pass）。在单张 RTX 4090 / 3090 上，Batch Size 设为合理值，3200 张图片的推理大约需要 1~2 小时。

### Step 2: 文本格式化与清洗 (Post-processing)

AI 生成的文本常包含不可见字符或随机冗余，直接算指标会导致误差。

- **操作**：写一个 Python 函数，遍历 `gt`、`pred_base`、`pred_finetuned` 三个文件夹中的文件进行清洗。
- **清洗规则**：
  - 去除行首行尾多余的空格和连续的空行（`strip()` 和 `re.sub(r'\n+', '\n', text)`）。
  - 将全角符号统一替换为半角符号。
  - 如果你在格式中定义了图片占位符（如 `[IMAGE_1234.png]`），由于每次生成的 ID 可能不同，使用正则表达式统一替换为泛化标签 `[IMAGE_TOKEN]`。

### Step 3: 多维度指标计算 (Metric Calculation)

这是简历上数字的直接来源。你需要计算预测文件（Pred）与标准答案（GT）之间的差异。分别计算 `Baseline vs GT` 和 `Finetuned vs GT`。

1. **宏观排版与字符还原度：归一化编辑距离 (Normalized Edit Distance, NED)**
   - **实现**：使用 `python-Levenshtein` 库计算字符串编辑距离。NED 越接近 1（或编辑距离越小）越好。
   - **意义**：衡量模型对复杂文档排版（换行、缩进、各级标题）的整体把控能力。
2. **核心难点攻坚：数学公式完全匹配率 (Math Exact Match / F1)**
   - **实现**：使用正则表达式 `(?<=\$).*?(?=\$)|(?<=\$\$).*?(?=\$\$)` 从 GT 和 Pred 中提取出所有的行内公式和独立公式。计算公式对齐和完全一致的比例。
   - **意义**：ArXiv 论文的核心难点在于公式。这个指标证明了你的微调没有破坏模型原有的公式解析能力，甚至可能因为你的自定义 `.mmd` 格式使其解析得更结构化。
3. **可选辅助指标：BLEU Score**
   - **实现**：使用 `nltk.translate.bleu_score` 计算。
   - **意义**：评估大段正文自然语言的生成流畅度。

## 阶段三：简历话术转化 (Resume Translation)

跑完上述流程，你将得到两组关键数据。此时，你可以将那个“花里胡哨且没有产出”的项目描述，彻底改写为高度专业、数据驱动的 AI 工程师工程履历：

**修改后简历项目描述示例（重点看加粗的量化结果）：**

- **项目背景**：针对学术文献复杂排版（多栏、图表、密集公式）的解析难题，基于 Swin-Transformer 与 BART 架构的 Nougat 模型进行领域自适应微调（Domain Adaptation）。
- **数据工程**：设计自动化 Pipeline，基于 LaTeXML 从 ArXiv 源码中构建并清洗了 **32,000** 高质量“图像-自定义MMD结构化文本”数据集，按 9:1 严格划分训练与留出验证集。
- **模型训练与部署**：在单节点 GPU 算力下独立完成数据加载器优化与模型全流程微调。解决长序列截断与过拟合问题，完成端到端验证。
- **量化产出**：在 3.2k 规模的测试集上进行消融评测。相比官方预训练基线模型（Baseline），微调后的模型在自定义结构化输出任务上，**整体归一化编辑距离（NED）得分提升 XX%，数学公式 Exact Match 准确率从 XX% 提升至 XX%**，成功实现了针对高密度学术文档的高精度、定制化结构解析闭环。
